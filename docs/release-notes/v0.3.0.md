go-xslt 0.3.0 adds a command-line tool, makes the library safe to run on untrusted input in a service, and runs every W3C conformance case the processor can be judged on — finding and fixing a dozen engine bugs on the way.

From this release on, **bug reports are welcome as [issues](https://github.com/tim-riep/go-xslt/issues)**; security problems go through [private reporting](https://github.com/tim-riep/go-xslt/security/advisories/new) (see [SECURITY.md](https://github.com/tim-riep/go-xslt/blob/main/SECURITY.md)).

## New

- **Command-line tool** `go-xslt transform | validate | xpath | version`, for pipelines and CI ([guide](https://tim-riep.github.io/go-xslt/guide/cli)). The options mean the same in every command: `-s/--stylesheet`, `-x/--schema`, the document is the last argument. Includes `--timeout`, `--max-steps`, `--max-output`, `--param-expr`, `--ns`, `--var`.
- **Resource limits** `engine.Limits{MaxSteps, MaxDepth, MaxOutputBytes}` per request. Runs started with `fn:transform` spend from the caller's budget.
- **Cancellation** with a `context.Context`: `TransformContext`, `TransformToContext`, `Stylesheet.TransformContext`, `EvalXPathContext`, `ValidateContext`.
- **Typed stylesheet parameters**: `ParamExprs` sets a parameter to the value of an XPath expression (`5`, `xs:date('2026-01-31')`, `map{…}`, `parse-xml('…')`).
- **XPath with namespaces and variables**: `XPathRequest.Namespaces`, `DefaultElementNamespace`, `Variables`, `VariableExprs`. The prefixes the document element declares, and `xs`, `fn`, `math`, `map`, `array`, … are bound automatically, so a UBL document's own prefixes just work ([guide](https://tim-riep.github.io/go-xslt/guide/xpath#namespaces)).
- **Embedded stylesheets** (XSLT 3.0 §3.13): with an empty `Stylesheet`, the stylesheet the source names in `<?xml-stylesheet href="#id"?>` is used.
- **Validation without schemas**: with empty `Schemas`, an instance is validated by its own `xsi:schemaLocation` hints and `xsi:type`.
- `xsl:number` spells out numbers in German, French and Italian.

## Desktop app

- **Light mode**: the settings (button at the right end of the toolbar) choose *System*, *Light* or *Dark*.
- **Update dialog**: when a newer release exists, the app shows its notes at start, with *Download*, *Later* and *Skip this version*. You will see it for the first time with the release after this one.
- The update check moved into the settings.
- The license list (*Licenses* in the toolbar) now names every bundled package, also the indirect npm dependencies such as dockview and the CodeMirror and Lezer packages.
- Linux, Windows and macOS builds as before; the unused Android and iOS template code is gone.

## Changed behaviour

Check these if you upgrade:

- Limit errors (step budget, recursion depth) have the code **`XPDY0130`** ("implementation limit exceeded") instead of `XTDE0040`.
- `xsl:result-document` without `format` is serialized by the **unnamed `xsl:output`**, as XSLT 3.0 §25.1 requires; before, it always used the XML defaults.
- `EvalXPath`: a prefix bound nowhere is the error **`XPST0081`**; before, it silently meant "no namespace" and found nothing. A syntax error has the code `XPST0003`.
- **`xmlns:p=""`** in an XML 1.0 document is rejected (Namespaces in XML 1.0, "No Prefix Undeclaring").
- **`xml:id`** values, and attributes the DTD declares ID/IDREF(S), are normalized when the tree is built (XDM 3.1 §6.3.3).
- An empty `Stylesheet` and empty `Schemas` were errors; see *New*.

## Security

Input that could crash the whole Go process is refused with an error instead: documents nested more than 10,000 levels, XPath expressions nested more than 5,000 levels, inline functions recursing more than 10,000 levels. The [security guide](https://tim-riep.github.io/go-xslt/guide/security) answers what the library reads, writes and limits, with a checklist for untrusted input.

## Fixed

- `fn:serialize` put spaces between nodes; only adjacent atomic values are separated (Serialization 3.1 §2).
- An element serialized out of its tree lost the namespaces it inherits.
- `fn:analyze-string` nested groups by position instead of by the pattern's parentheses.
- `fn:json-to-xml` lost an empty key (`key=""`); `parse-json` and `json-to-xml` now ignore a leading byte-order mark.
- Ranges (`to`) over integers beyond 64 bits were silently clamped; they are now exact.
- `substring()` with `NaN` or huge arguments, and `math:exp`, gave platform-dependent results.
- XSD 1.0: a new schema location hint for a namespace already used is an error (§4.3.2).
- `@xml:id` found nothing in `EvalXPath` without namespace bindings.

## Conformance

All four measurements run every night on Linux and match the published numbers ([details](https://tim-riep.github.io/go-xslt/conformance)):

| Suite | Passed |
|---|---|
| XSLT 3.0 | 8,635 of 8,647 (99.9%); with all optional features 12,288 of 12,317 (99.8%) |
| XPath 3.1 / F&O 3.1 | 22,419 of 22,478 (99.7%) |
| XSD 1.0 / 1.1 | 39,396 of 39,401 / 41,549 of 41,553 (99.99%) |

The test harnesses no longer skip anything on their own account: cases are only left out when they test something outside the processor's definition (XQuery, or a variant written for a processor without a feature go-xslt has). Every remaining failure is documented with its reason.
