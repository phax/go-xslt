go-xslt 0.3.9 closes the two remaining issues reported by Philip Helger: a crash in the XSD compiler and the general argument check for built-in functions. Every W3C conformance number is the same as in 0.3.8.

## Fixed

- **Stack overflow on a union type that reaches itself** — an XSD 1.0 schema whose union lists itself as a member type (directly, through other unions, or through an inline type naming the enclosing one) ended the process with a fatal stack overflow. The compiler now keeps every simple type free of cycles: a cycle through a restriction base or list item type is a circular derivation, XSD 1.1 rejects a union cycle, and XSD 1.0 collapses it to the member types that do not lead back ([#12](https://github.com/tim-riep/go-xslt/issues/12)).
- **Argument types of every built-in function** — 0.3.8 fixed four reported cases; now the arguments of all 197 `fn:`, `math:`, `map:` and `array:` functions and the XSLT functions (`key`, `document`, `current-group`, …) are checked against their declared signatures by the XPath 3.1 function conversion rules before the function runs. A wrong type or number of items is a type error (XPTY0004), for a direct call, a named function reference, `function-lookup`, a partial application and a dynamic call alike. Expressions that were accepted before, such as `upper-case(1)` or `contains(//title, 'x')` over several nodes, now raise XPTY0004 as the specification requires; XSLT 1.0 compatibility mode keeps its lenient conversions ([#9](https://github.com/tim-riep/go-xslt/issues/9)).
- `format-integer` no longer panics on NaN in XSLT 1.0 compatibility mode.
