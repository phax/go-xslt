go-xslt 0.3.3 completes the entity-expansion fix of 0.3.2 and parses XML about a third faster. Everyone who parses XML they do not control should update.

## Security

**The entity-expansion limit of 0.3.2 was checked too late** ([GHSA-6xxr-4cc9-4m89](https://github.com/tim-riep/go-xslt/security/advisories/GHSA-6xxr-4cc9-4m89)). It compared the size of an entity value with the limit only after building it, so a 699-byte document whose entity referenced a 10 MB entity a hundred times allocated about 5 GB before it was refused, and a slightly larger one about 50 GB. Parameter entities (`%name;`) in the internal subset were not limited at all. Now nothing is built past the limit: entity values and parameter entities are checked before each substitution, and the streaming reader hands documents with long entity values to the full parser, which applies the limit. The regression tests measure the memory allocated, not only the error.

## Faster parsing

The XML parser runs on its own tokenizer instead of Go's `encoding/xml`. It reads names and values directly out of the document instead of copying them, which saves about 260 MB and 9.5 million allocations on a 37 MB document: copying, sorting, grouping and validation take about a third less time. It accepts and rejects exactly what `encoding/xml` did, with the same error messages; this is checked by comparing both on hundreds of millions of generated inputs and on all files of the W3C test suites, including the W3C XML Conformance Test Suite.
