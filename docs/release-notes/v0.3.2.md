go-xslt 0.3.2 fixes a denial-of-service in the XML parser. Everyone who parses XML they do not control should update.

## Security

**Entity expansion was unbounded.** A document of a few hundred bytes whose DTD declares entities that refer to each other ("billion laughs") made `Transform`, `EvalXPath`, `Validate` and the command-line tool expand text without limit: the call hung, ignored its `context.Context`, and could exhaust the memory of the whole process. Entity expansion is now limited to eight times the size of the input, and at least 16 MiB; beyond that the document is refused with a parse error. Ordinary documents, including ones that use many entities, are not affected.

The limit covers entity values that refer to each other, entities containing markup, many references to one entity, and the streaming reader. The details are in the [security advisory GHSA-3qwg-cpmj-qx68](https://github.com/tim-riep/go-xslt/security/advisories/GHSA-3qwg-cpmj-qx68) and the [security guide](https://tim-riep.github.io/go-xslt/guide/security#resource-limits).

## Fixed

- An unterminated `DOCTYPE` with an internal subset (`<!DOCTYPE[<!ENTITY …`) gave "internal engine error" instead of a parse error.

## Also in this release

- Faster: one evaluation context per XPath evaluation is reused instead of allocated, `xsl:sort` atomizes each key once, and XSD validation checks numbers and dates without building values. Validation takes about 20% less time, sorting and template-heavy transformations 10–20% less. All W3C conformance numbers are unchanged.
- Every exported name in `engine` and `xsd` has a doc comment.
- The macOS apps are notarized with an App Store Connect API key.
