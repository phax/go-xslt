go-xslt 0.3.6 is faster: transformations now run quicker than with libxslt across the board, and XSD validation is within 1.13× of libxml2. Results are unchanged; every W3C conformance number is the same as in 0.3.5.

## Faster

| Workload (37 MB input) | ratio to libxslt / libxml2 in 0.3.5 | in 0.3.6 |
|---|---|---|
| copy the document | 0.90× | 0.81× |
| recursive apply-templates | 1.11× | 0.85× |
| Muenchian grouping | 0.96× | 0.78× |
| XPath predicates and functions | 0.71× | 0.72× |
| XSD 1.0 validation | 1.34× | 1.13× |

- Simple match patterns such as `node()`, `@*` or a plain element name, and `apply-templates select="@*|node()"`, are matched without building a full evaluation context.
- `xsl:sort` uses a faster sort where the result is provably the same; `key()` indexes are prepared once.
- Copies of subtrees allocate their nodes in small blocks.
- XSD validation checks integers, decimals and names with hand-written scanners instead of regular expressions.

The benchmark's sort comparison is no longer published: on macOS it measured a text-output problem in the old libxslt version Apple ships, not sorting. Details on the [performance page](https://tim-riep.github.io/go-xslt/performance).
