go-xslt 0.3.8 fixes four issues reported by Philip Helger. Every W3C conformance number is the same as in 0.3.7.

## Fixed

- **`package-version` ranges with a prefix as upper bound** — `xsl:use-package package-version="to 3.3.*"` or `"1 to 5.*"` was rejected with XTSE0020. Both forms are valid and now match every version up to the prefix and every version that starts with it ([#8](https://github.com/tim-riep/go-xslt/issues/8)).
- **Booleans in arithmetic** — `1 + true()` gave 2; a boolean is no arithmetic operand, so it is now a type error (XPTY0004), outside XSLT 1.0 compatibility mode ([#10](https://github.com/tim-riep/go-xslt/issues/10)).
- **`attribute(N, T?)`** was accepted; the `?` belongs to `element()` tests only, so it is now a syntax error ([#11](https://github.com/tim-riep/go-xslt/issues/11)).
- **Argument types** — `contains-token`, `math:atan2` and `fn:error` now reject an empty sequence where a value is required, and `fn:error` no longer takes a string as its error code ([#9](https://github.com/tim-riep/go-xslt/issues/9), the reported cases; a general check for all built-in functions follows).
