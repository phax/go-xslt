go-xslt 0.3.7 is faster than libxslt and libxml2 on every workload both can run — XSD validation included — and fixes the handling of attribute defaults declared in a DTD. Every W3C conformance number is the same as in 0.3.6.

## Faster

| Workload (37 MB input) | ratio to libxslt / libxml2 in 0.3.6 | in 0.3.7 |
|---|---|---|
| copy the document | 0.81× | 0.62× |
| recursive apply-templates | 0.85× | 0.68× |
| Muenchian grouping | 0.78× | 0.59× |
| XPath predicates and functions | 0.72× | 0.53× |
| XSD 1.0 validation | 1.13× | 0.81× |

- Whitespace in attribute values is normalized only where a value actually contains a tab or line break, instead of in a separate pass over the whole document.
- The parser writes nodes straight into preallocated blocks and numbers document order as it goes.
- `xsl:copy` builds from per-run blocks; several XPath functions and `generate-id()` no longer build intermediate lists.
- XSD validation allocates almost nothing per element (from 2.7 million allocations to about 20,000 for a 37 MB document).

## Fixed

- Attributes with a default value declared in the DTD (`<!ATTLIST e a CDATA "x">`) were added in a random order, so the same document could serialize differently from one run to the next. They are now added in declaration order.
- When an attribute is declared more than once, the first declaration now counts, as XML 1.0 §3.3 requires; before, the last one did.

Details and how to reproduce the numbers: [performance](https://tim-riep.github.io/go-xslt/performance).
