go-xslt 0.3.5 is a security and correctness release. Update if you use the library on input you do not control, or run the desktop app or the command-line tool.

## Security

- **`golang.org/x/text` updated to v0.39.0** ([GHSA-x6hj-m328-hffh](https://github.com/tim-riep/go-xslt/security/advisories/GHSA-x6hj-m328-hffh), [GO-2026-5970](https://pkg.go.dev/vuln/GO-2026-5970)): an infinite loop on invalid input. go-xslt reaches the affected code through `normalize-unicode()`, collations and HTML serialization, so a crafted string in an expression or a document could make a call hang. This affects every program that imports the library; updating to v0.3.5 brings the fixed version.
- **The binaries are built with Go 1.26.10.** The desktop apps and the command-line tool of earlier releases were built with Go 1.25.0, which lacks a year of security fixes to the standard library (`net/http`, `crypto/tls`, `crypto/x509`, `net/url`, `encoding/xml`). Go 1.26.10 also distrusts the compromised intermediate certificates of an Indian certificate authority ([GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)), which matters for the library's optional network access and the app's update check. The library itself still needs only Go 1.25.
- CI now runs `govulncheck` on every change.

## Fixed

49 cases where valid input gave a result the W3C specifications rule out, found by new unit tests written against the specifications. Among them:

- **XPath:** `Q{uri}*` respects the namespace; `xs:duration('P1M') eq xs:duration('PT2629746S')` is false; the default priorities of `.` and `except`/`intersect` patterns; regular expressions with back-references under the `s` flag and with character-class subtraction.
- **Functions:** `parse-json('1E400')` is INF; JSON output escapes U+007F–U+009F; adaptive serialization of decimals and typed values; arrays are flattened for the xml and text methods; `replace` with the `q` flag; `format-date` with `[F]`, widths and padding; `deep-equal` ignores comments and processing instructions; `unparsed-text-lines`; `current-dateTime()` is an `xs:dateTimeStamp`.
- **XSLT:** `xsl:number` on attributes and processing instructions; `default-mode` as the initial mode; namespaces when copying (`xsl:copy` of namespace nodes, `copy-namespaces`, `inherit-namespaces`, prefixes for namespaced attributes); `xsl:where-populated`; `xsl:message/@error-code`; `$err:description`; hidden and private components in packages; `use-when` on the root element; `xsl:merge` keys compared by type and collation.
- **XSD and XML:** two valid schemas were rejected; NaN and dateTimes without timezone against bounds; list enumerations compared by value; type alternatives no longer see the element's children; a schema that made the compiler fail internally. Documents with recursive entities or without a root element are now rejected as not well-formed.

All W3C conformance numbers are unchanged.

## Also

Unit-test coverage, measured without the W3C suites, is 88% (was 57%).
